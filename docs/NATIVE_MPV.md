# 可选 MPV 后端接入

完整源码配方由 [native-mpv-sources.json](native-mpv-sources.json) 固定，许可补充来源由 [native-mpv-notices.json](native-mpv-notices.json) 固定；[运行库清单](native-mpv-runtime.json) 校验这两份文件及 C API 头文件的指纹。MPV、OHOS FFmpeg fork、libplacebo、TLS、AV1、Lua、LCMS、Dolby Vision 和子依赖使用明确归档及 SHA256，不使用可变分支头。

`scripts/build-native-mpv.py` 使用本机 OHOS SDK 和独立目录中的固定 Rust 工具链构建完整运行库；当前构建主机为 macOS arm64，目标为 arm64-v8a。首次构建需要下载固定归档及原始 Cargo.lock 声明的包；`--offline` 只使用已校验缓存，`--check --offline` 只验证当前配方与 SDK 对应的已有构建。脚本不运行 rustup、cargo install、上游依赖同步器或下载归档中的安装脚本。字体字幕栈复用 `scripts/prepare-native-ass.py` 的已验证构建。

`scripts/prepare-mpv-notices.py` 收集源码内实际许可文件、SPDX LICENSES 目录、Rust 标准库及其锁文件闭包、编入 Dolby Vision 静态库的 Rust 包，以及 SDK 提供的通知。少数 crate 未携带完整通知时，使用其原始 VCS 记录对应的固定上游提交补充，补充归档同样校验 SHA256。标准库闭包包括其他平台或仅构建所需的包，不表示这些包均在 OHOS 上运行。现有字体栈通知保留在相邻的 `third_party/ass`。

构建入口调用 `scripts/prepare-native-mpv.py`，校验源码构建收据、AArch64 库及与其匹配的通知后，统一发布至库和 rawfile 目录；中途失败会回滚已有输出。已有可信缓存时可运行 `python3 scripts/prepare-native-mpv.py --offline`。每次构建的精确库指纹和通知指纹记录在忽略目录的 `prepared.json` 中，不把带本机路径的构建收据写入可复用文档。生成的运行库和 MPV 通知目录均不提交，HAP 构建前由准备步骤生成。

`libcineisle_mpv.so` 是应用自己的异步桥接，不直接链接 `libmpv.so`；只有能力检查和实例创建会动态加载可选运行库。应用仍以 API12 为最低基线。当前源码库导入的公共 SDK 声明最高始于 API15，因此 API15 以下不尝试加载；这不构成物理 API15 兼容性证明。SDK 头文件和导入集合按已核对的配方检查，更新 SDK 接口时需要重新验证。其他 ABI 必须另行固定并验证依赖。

旧预编译发行包的完整传递源码修订未被当作已证实。本分支采用明确来源重新构建，不宣称与旧发行二进制逐字节相同；构建特性和实际媒体能力分别核对。源码归档、补丁和构建脚本须随匹配的项目源码一起提供给二进制接收者，通知索引本身不包含那些源码归档。

固定Android基准的MPV配置明确设置`tls-verify=no`，当前候选库的默认值与其一致。TLS依赖编译成功不等于实际HTTPS、鉴权、重定向与异常取消已经验收；相关网络矩阵继续独立验证，不能把新建的严格CA策略当作基准已有功能。

每个桥接实例在独立工作线程上串行执行命令；原生实例上限为4，每实例最多保留64个待执行普通命令。饱和时拒绝普通命令，释放不受容量门禁阻断；重复释放等待同一销毁结果，关闭后拒绝旧句柄。创建失败会等待清理，释放关闭队列并等待原生销毁。控制器拥有离线文件描述符，`fd://` 借用该描述符，后端释放完成后才由控制器关闭。音频使用公共 AudioSessionManager，焦点获取和释放按进程内所有者串行处理。现有实现监听会话停用事件并请求暂停，恢复必须来自明确的播放请求。音频流临时中断不一定停用整个会话，因此会话事件不能替代渲染器中断通知；源码构建已加入 OHAudio 回调到 MPV 核心暂停的补丁，其他焦点策略仍需分别验证。最后一集结束时先释放音频焦点，再发布完成事件供队列处理；显式重播重新获取焦点并跳回开头。迟到的EOF快照不得覆盖新的播放请求或未确认跳转，清理期间退出也会等待焦点释放。焦点清理失败仍保留所有权，交由释放重试，不能把清理失败当作已交接。

[原生中断补丁](../native/mpv/ohaudio-focus-loss.patch)针对固定 MPV 源码提交，使用始于API10的渲染器回调，经线程安全AO事件通知播放器线程设置真实暂停状态。适配器在已确认播放后发现核心主动暂停时，同步撤销播放意图并释放会话；原生与会话双重通知只处理一次，迟到的命令确认不得释放后来显式播放取得的焦点。该补丁已纳入完整源码构建；裁剪的诊断库不能替换完整产品运行库。源码构建、许可打包与实际媒体/生命周期验收分别留存证据。

本地回归入口为 `node tests/run-regression.cjs`。新增适配器回归覆盖延迟快照、取消与晚到创建、重复释放、轨道身份、跳转确认、焦点获取、抢占、交接和清理失败；运行库准备回归覆盖缓存、指纹、ABI、头文件和归档边界。SDK 编译、原生解码、实际音频焦点、产品 Player/PiP/后台生命周期、物理设备和真实 Jellyfin 必须分别验证。

设置页通过 `EnginePreferences` 保存应用级引擎选择，默认使用 AVPlayer，账户切换与退出不清除选择。仅在 Preferences 写入并刷新成功后发布新值；读取失败或值损坏时保留原始数据，由用户明确修复。设置改变影响后续打开的视频，当前实例继续使用原引擎。`PlaybackEngines` 在创建实例时分派真实后端，MPV 不可用时显示错误；系统播放器由用户明确选择。API15 以下禁用 MPV 选择，设置页的版本资格检查不触发可选库加载。

内嵌 SubRip 通过 MPV 的完整活动 Dialogue 包转换到共享字幕层，保留可表示的强调、颜色、字体、相对字号、独立位置和重叠字幕，并跟随系统字幕样式及画中画窗口。转换只接受已支持的标签和默认事件元数据；遇到未知样式、特效、溢出或其他字幕编码时，保留原生视频渲染，避免丢失作者排版。ASS/SSA 和位图字幕仍由 MPV 渲染，不能据此宣称它们已支持共享层的系统样式。外挂文本及 ASS 继续走已有缓存和渲染链路。

MPV 的原生 ASS 使用 `AssFonts.prepare` 按公共平台字体清单生成的映射，与外挂 ASS 共用字体策略。播放器把当前 Ability 的缓存目录传给工厂，适配器准备映射后按实例交给原生桥接；字体准备失败时保留播放错误。受控源码补丁增加 `sub-fonts-config`，让 libass 在 `config=no` 和 `load-scripts=no` 下显式读取这份字体映射，不修改进程全局环境，也不为加载字体开启通用配置或脚本搜索。源码运行库更换后必须重新核对作者 ASS 的实际字形，不能仅检查视频帧或字幕事件存在。

内嵌PGS由原生解码器显示，独立字幕轨开关、跳转清屏、后续字幕及PiP跟随视频输出。Matroska中的受支持字体附件由该实例的libass读取，不导入系统字体或其他播放实例；受支持字体仍需用有/无附件对照核对字形及实例间隔离。该支持不把图片轨转换为离线文本缓存，也不承诺其他图片格式、所有字体格式或任意媒体均兼容。

每次跳转都使字幕发布缓存失效，即使原生跳转在两次轮询间完成、前后仍是同一句字幕，也会重新发布，避免控制器清空字幕后无法恢复。画中画保留常规行数上限，并使用扣除边距后的实际高度容纳放大的系统字幕；窗口确实放不下时仍有行数限制，不能承诺任意长字幕在任意小窗中完整显示。

`PlaybackSurface` 使用API12的`onSurfaceChanged`回调获取物理像素尺寸，经控制器缓存并转发到MPV的`ohos-surface-size`，不把ArkUI的vp直接当作像素。引擎等待原生视频输出就绪，并回读`osd-width/height`确认；初始化或视频输出重配置后尺寸与目标不一致时会重新同步。连续变化合并到最新尺寸，关闭后的迟到回调不会恢复实例。AVPlayer继续由平台管理Surface尺寸。该链路同时覆盖全屏、竖屏和PiP尺寸变化。

缓存策略对照固定Android基准中的`MPVPlayer.kt`：对本地和网络媒体显式启用缓存及初始缓冲，前向和后向各限制为32MiB。自动缓存会使本地媒体不进入同样的可跳转缓存路径；不能把该差异误判为字幕排版问题。容器索引及字幕预读仍有自身限制，不据此保证任意长文件、长对白或容器的所有跳转都能恢复字幕，也不为单个样本任意增加预读时长。

可选后端共用现有产品播放器、系统播放、PIN、队列、后台和PiP链路；默认仍为AVPlayer。实际媒体、字体、HTTPS/鉴权/重定向/负向网络、音频抢占、自动PiP和后台策略分别验收，源码与SDK编译不能替代原生运行。目标物理API12/15设备、真实Jellyfin、可听音频与长期行为仍须独立核验，不据有限样本承诺全部编码、字体、硬解或vo/ao兼容性。构建配置中的 `gpl=false` 不能替代对库及其依赖的来源和许可核对。
