# 开发规范入口

规范采用“基础约定 + 专题按需读取”。基础约定与唯一触发路由表位于根目录 [AGENTS.md](../AGENTS.md)，所有任务适用；这里是使用说明，不重复维护规则或路由。

## 使用方式

1. 明确本次准备改变的行为、涉及的文件和外部边界。
2. 按 AGENTS.md 的路径或行为触发条件，读取相关专题；不预读全部文件。
3. 跨职责取并集，同一任务中不重复读取。新文件依据职责选择专题；扩展范围前补读。
4. 如需查看专题引用的平台/格式资料，只读取此次变更相关部分；普通链接不表示递归加载整个文档集合。

这里的“按需加载”由 AGENTS.md 明确要求执行者在修改前读取对应文件，不表示链接内容会由工具自动注入上下文。避免用服务目录下的大型 AGENTS.md 把所有专题一起加载。

## 典型任务

以下是选择过程的示例，实际仍以本次改动为准，不能作为排除其他专题的白名单。

- 只修正文档措辞：基础约定即可；准备提交时再读交付专题。
- 调整一个页面的样式：读 UI 与资源；需要修改交互测试时补读测试与验收。
- 新增带偏好保存的设置项：读 UI 与资源、架构与规则、存储与安全、测试与验收；涉及异步提交/晚到结果时补读异步与生命周期。
- 提取同步重试策略：读架构与规则、异步与生命周期、测试与验收；涉及持久化重试状态校验时补读存储与安全；改变错误分类时补读传输与错误。
- 调整字幕资源契约：读架构与规则、原生与媒体、测试与验收；若涉及下载、文件或生成流程，分别补读相应专题。

## 维护方式

- 规则在一个专题内维护，不复制到所有模块；其他专题仅指向发生交叉时需关注的边界。
- “必须”是新代码及本次变更的要求；“建议”按实际复杂度采用。存量问题按职责逐批治理，不因规范更新而全仓重写。
- 增加新专题时同时更新 AGENTS.md 的触发条件，说明适用范围；不把本次任务计划、审计结果和历史日志写进规范。
- 文档约定不等于自动 lint 或 CI 门禁已经实现。自动化只检查能可靠判定的契约，不建立“禁止一切字面量”的规则。
- 本规范沿用固定功能基准；待迁移功能仍需更新迁移清单并补验收。分支流程以 [分支约定](BRANCHING.md) 为准。
