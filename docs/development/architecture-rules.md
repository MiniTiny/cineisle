# 架构与规则

适用：新增模块/公共接口，调整依赖、业务规则、枚举、默认值或共享常量。

## 职责边界

| 归属 | 应负责 | 不应承担 |
|---|---|---|
| 页面与组件 | 展示、交互、可访问性、视图状态 | REST 拼装、直接文件读写、重试/配额/推荐决策 |
| 用例与业务策略 | 业务操作、规则、所有权、副作用协调 | ArkUI 样式、SDK 错误文本解析 |
| 协议与平台适配 | 传输、DTO 映射、SDK/存储/媒体桥接 | 首页展示数量、推荐权重、界面文案决策 |
| 类型与纯计算 | 业务值、解码校验、规则计算、单位换算 | 引用页面、隐式读取环境、启动任务或 I/O |

- 禁止新增循环依赖或反向依赖页面获取规则。现有 utils 位置不代表内容应全局共享；模块按用途命名。
- 优先扩展现有 UiPalette、UiLayout、Options、Store 与适配层；仅在真实复用、复杂边界或隔离需求出现时引入接口。
- 规则计算尽量保持纯函数，时钟、随机数与 I/O 有明确可控制的边界。

## 常量与策略

- 业务阈值、配额、容量、超时和重试参数；多处共享的同一规则；格式/协议/桥接/安全值；单位或来源不明显的值，都必须明确归属并具名。
- 索引、空值、自然常数、清晰的局部几何可留在局部。协议 magic、位移和算法系数留在所属模块并说明依据。
- 相同数字不代表相同规则；同一规则不能因单位不同而分别维护。名称表达用途和单位，例如 initialRetryDelayMs、maxTransferBytes，避免 TIMEOUT_30000、MAX_SIZE。
- 用户偏好模块统一维护默认、规范化、校验与界面需要的范围。不要再建立一套平行配置；只有真实配置需求才增加可配置项。
- 禁止混合职责的全局 Constants，也不为消除字面量而把全部值外置。

## 类型与可读性

- 枚举、导航状态与选项值有明确类型；展示标签与业务值分离，避免平行数组按下标对应。
- 类型、强制转换和编译通过不能代替外部数据校验；未知值、缺失、损坏与版本不兼容的处理必须明确。
- 遵守本机 ArkTS/SDK 约束；路由、共享状态键与桥接字段形成契约。装饰器若只能使用字面量，保留并验证一致性，不绕过平台约束。
- 重要分支、状态变更和副作用分行表达；注释解释原因、平台限制与兼容边界。按职责拆分长函数，不设机械行数或抽象层数指标。
