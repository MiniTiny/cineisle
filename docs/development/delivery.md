# 交付

适用：准备提交、推送、PR、合并或发布时读取；开始实现并不要求提前加载完整发布流程。

- 分支流程读取 [分支约定](../BRANCHING.md)；发布或功能验收范围同时读取 [验证说明](../VALIDATION.md) 的相关部分。
- 从 develop 建 feature 分支，通过 PR 面向 develop；不直接开发 master，不使用 main。
- 一个批次聚焦一个职责；常量提取、行为调参、存储迁移、依赖升级与格式化分别提交和评审。
- 提交前核对路径、暂存范围、凭据与用户原有修改，使用正常 hooks。仅提交已验证的本次范围，不带入未跟踪编辑器配置或本地审计。
- PR 说明具体问题、最终行为/结构、保留的兼容边界、当前验证与未运行验收，不复述过程或把计划写成已完成。
- 功能/行为变化同步必要迁移清单与验收；规范文档保存可复用规则，执行计划与历史证据保留在 `.local`。
- 推送/合并按已有用户授权执行；核实远端、分支、提交范围和最新状态，不重复索取已给出的授权，不强推覆盖他人更新。
- 推送后核对远端 SHA；PR/合并/发布状态分别报告，不以分支名称、构建成功或测试数量代表发布验收。
